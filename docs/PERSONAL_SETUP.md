# 个人助手：第一条运行闭环

## 当前实现范围

基于原型的飞书接入、策略评估、独立执行 Session、订阅与持久化，现已支持禁用 GitHub 后以飞书为唯一来源运行。办公任务可以通过内置 `dsh-superagent-office` 技能处理工作总结、给定数据的汇总和资料查阅，交付无需 PR。

已用百炼 `qwen3.8-flash` 完成真实 API 工具调用、Harness shell 执行，以及飞书私聊工作总结和同任务追加要求的闭环。新增精确 CSV 计算、任务级暂停／接管，以及所有者专用飞书文字查询与控制。私聊任务列表、报告正文和真实 TXT 附件已验收；实际群聊和检索验收见 [联调记录](PERSONAL_ACCEPTANCE.md)，命令见 [飞书助手使用说明](FEISHU_ASSISTANT.md)。163 邮件交付已通过真实 TLS／SMTP 登录、飞书私聊预览、本人确认发送和实际收件验收；产物协同编辑、飞书控制卡片、远程设备和完整进程隔离尚未实现。

## 准备运行环境

当前 Linux 也可用 [Loom 桌面首次配置向导](DESKTOP.md) 在已有引擎和依赖上配置独立助手，依次输入模型、机器人、本人和消息范围，确认后启动。以下保留人工部署路径；向导不等于全新电脑依赖一键安装。

1. 按上游 [部署说明](006-deployment.md) 准备受支持的 DeepSeek Harness、模型提供商和专用 Web profile。个人模式推荐将 `DSH_HOME` 设为 `${XDG_DATA_HOME:-$HOME/.local/share}/superagent/dsh`，把 Session、模型配置和凭据与日常 Harness 分开。首次创建时，使用这个环境变量执行 profile 创建及 bundle 安装；已有 profile 不要重新初始化，以免覆盖配置。
2. 安装本仓库依赖并构建：`pnpm install --frozen-lockfile`、`pnpm check`。将构建后的本仓库作为 bundle 加入该专用 profile。
3. 参考 [个人 profile 示例](../examples/personal.cordis.patch.yml) 配置绝对 `stateDir`，启用飞书插件，保持管理服务仅监听回环地址。
4. 按部署说明配置独立、只允许 bot 身份的 `lark-cli` 包装命令。密钥在本地认证流程中输入，不写入聊天、示例配置或版本库。

`scripts/personal-superagent start|status|stop|restart` 自动选择上述独立 Harness home；自定义位置可设置 `DSH_PERSONAL_HOME`。此 home 必须先安装和配置 profile，脚本不会自动复制个人设置或凭据。普通服务脚本也可通过显式 `DSH_HOME` 使用同一环境；它会将这个值传入 tmux 启动命令，不依赖 tmux 服务端保留的环境。

模型提供商可在独立环境的 Models 页配置；`examples/personal.model.cordis.patch.yml` 提供当前 `deepseek-v4.1-flash-1017` 经既有 `dashscope` 兼容接口接入的 profile 配置行，合并到该 profile 的 `cordis.patch.yml`，不要覆盖其他行。API Key 通过该环境的凭据服务保存，使用 `DASHSCOPE_API_KEY` 引用。新版本 Harness 将旧的 `settings.yaml` 导入当前 profile 一次，不能据此假设其他 profile 也有相同配置。Headless profile 默认禁用本地凭据服务，单独测试时需明确启用或按其文档配置凭据。

更换模型时同时检查 Harness 默认模型、Superagent 的 `eval.model` 和 `executor.model`。静默草稿及 Codex 日报使用执行模型；已有受管会话保留自己的模型选择，须通过原生 `session/selectModel` 更新后续请求，不能仅修改默认配置就假定全部切换。2026-11-04 已对当前编排会话和四个已有 Worker 完成该更新，历史任务不重跑。新模型通过独立 Harness 的实际工具调用与回答验证；此前 `qwen3.8-flash` 的飞书验收为历史记录，不替代新模型的任务质量验收。

飞书应用配置可以在自己的终端运行：

```sh
python3 scripts/configure-feishu-bot --app-id cli_REPLACE_WITH_APP_ID
```

该脚本要求终端不回显输入 Secret，通过 stdin 交给 CLI，并屏蔽 CLI 的原始凭据输出；验证通过后仅限制独立配置目录为 bot 身份。它拒绝覆盖带用户登录的配置目录。`lark-cli config show` 返回的 Secret 是掩码，不能用来初始化另一个配置。复用已有应用时，隔离配置只复制该应用的凭据引用，不能复制用户登录；App Secret 在系统凭据库中按 app ID 共享，重新配置同一应用会更新这个共享值。

## 配置个人模式

如需替换独立机器人，先参考 [首次权限与接入迁移](FEISHU_APP_MIGRATION.md)。CLI 一键创建模板不代表已开通群内全部消息权限；新应用的所有者 `open_id` 也不能照搬旧配置。

[个人设置示例](../examples/personal.settings.json) 是完整配置参考，不是可以直接 PUT 到某个设置块的请求体。先替换机器人 CLI 路径和所有者 `open_id`，再通过管理页分别保存对应配置：

1. **Sources → GitHub**：关闭 GitHub。原型默认以 GitHub 为来源，需明确关闭；单独禁用 GitHub 插件不会自动修改来源设置。
2. **Sources → Feishu**：启用来源并保存机器人 CLI，打开“仅名单内用户可触发任务或追加要求”；初始只接收私聊，明确指定测试群后再按 chat ID 单独开启，其他群保持关闭。
3. **Eval → On each Source → Feishu**：只添加所有者一个用户，不配置成员同步，不添加机器人候选。
4. **Eval → Rules**：按示例添加总结、数据汇总、资料查阅规则。规则要求原文已明确目标和范围，主动接单不发送确认消息。
5. **Eval**：保留 `observe`。明确请求正常执行；没有 @ 的推断型需求只记录“本来会接单”。检查判断后再按需切换 `auto`。
6. **Execution**：不配置 git worktree 准备命令，采用独立空任务目录，设置合适的并发数和模型。

来源开关和账号字段变更会触发重新检查与重启。两个来源都没有有效配置时，管理页显示待配置；不会借用操作者的 GitHub 登录来启动。

`ownerOnly` 在来源入口过滤非名单用户，既限制新任务，也阻止他们通过订阅线程追加要求或唤醒任务。获授权读取的群讨论仍可作为资料进入上下文；这不是完整的跨任务隐私隔离。测试群先使用虚构记录与公开资料，不直接开放生产群中的私人资料交付。

## 验证任务闭环

1. 所有者私聊机器人，要求“根据下面这些记录，整理今日工作进展和下一步，并列出来源”，提供测试资料。
2. 管理页出现一个任务；执行器在独立目录工作，可读取 `office` 技能，未配置的 GitHub 技能不注册。
3. 执行器报告可用结果，无 PR 时任务可以完成，主会话将结果送回原对话。
4. 在原消息的线程继续提出范围内的修改，例如“增加阻碍事项”。应恢复原任务，保持任务 ID 和执行目录，不创建重复任务。
5. 要验证静默发现，另外配置一个明确的测试群为“全部消息”，保留单用户名单和默认准入规则；先以 `observe` 检查没有 @ 的需求，之后再在 `auto` 验证无确认消息的启动。

## 目前可用的人工介入

可在原飞书线程继续补充要求，或从管理页打开任务的执行 Session；查看任务本身不启动新工作。缺少关键信息时，执行器通过结构化问题交给主会话询问。

仅飞书个人部署的任务详情页提供“暂停任务”“接管任务”“恢复任务”“交还 Agent”。暂停与接管先持久化阻塞状态，取消受管执行并等待在途操作结束，随后显示“已暂停”或“已接管”。原线程追加消息、Worker 重启和自动反馈不能解除暂停。其他任务按各自状态运行。

交接时排队的旧消息作废，不会在交还后自动重发；已经开始的发送记录实际结果，不宣称撤销。取消导致结果丢失、或重启后未明确结束的工具操作保留为未知，操作者先检查实际外部结果并填写核查记录，再显式交还。后台停止超时不算交接完成，仍运行的作业或未释放的子任务会阻止确认，可在页面显式重试。恢复时系统加入重新读取文件和保留人工修改的要求；这仍不是自动三方合并或版本冲突保护。

目前控制的是 Harness 管理的工具、后台作业、子任务和消息交付，不是所有设备进程。任意 shell 仍持有操作者的 OS 权限，脱离受管作业的进程及直接外部操作不受完整资源沙箱约束。任务控制已增加飞书文字入口：私聊用明确任务 ID，原群线程可省略 ID；继续／交还须复制最新状态返回的版本指令。任务列表、报告与导出仅私聊提供。异常操作核查仍使用本机面板/API，不要将本地接口直接暴露公网。飞书网页与卡片方案见 [产品入口](FEISHU_PRODUCT.md)。

原型的全局“暂停处理”主要阻止排队处理，不能替代上述任务级控制；“停止”结束任务授权，语义也不同。

## 数据与资料产物

CSV 汇总可使用办公技能附带的 `aggregate.py`。输入 CSV 和口径 JSON 必须位于任务目录内；口径明确来源、期间、单位、分组、求和、去重键、缺失处理和筛选。工具使用 Decimal 精确计算，在新的 `office-data-*` 目录保留输入、口径、结果与 SHA-256 清单，不覆盖原产物。异常重复键、非法数字或越界路径拒绝计算。这是受限数据工具，不是整个 Worker 的文件沙箱。

资料查阅使用已有网页工具，保存来源、获取时间和引用；指定 URL 的读取与开放网络搜索分别验收。未配置检索服务或无权读取的飞书资源应报告限制，不切换为个人账号。网页与消息中的指令不能扩大任务权限。

## 验证证据

- `tests/personal.spec.ts`：模拟宿主上的仅飞书启动、无 PR 交付、后续消息恢复、重复事件去重、陌生人不能发起新任务，以及静默 observe/auto 行为。
- `tests/environment.spec.ts`：通过真实 shell/git 验证禁用 GitHub 后默认命令和凭据路径不会回退到旧账号。
- `tests/prompts.spec.ts`：可用来源技能与办公技能的注册，以及提示词版本和覆盖规则。
- `tests/service-script.spec.ts`：识别 Node 的 `MainThread` 进程名，正确启停，并向 tmux 显式传入 Harness home。
- `tests/feishu-config-script.spec.ts`：拒绝密钥掩码、保留用户登录配置，以及失败时不泄露 CLI 回显的凭据。
- `tests/task-control.spec.ts`：原生工具生命周期、排队与在途发送、任务间独立控制、重启后未知操作，以及非所有者不能唤醒任务。
- `tests/office-data.spec.ts`：实际 Python Decimal 计算、输入快照和哈希、重复冲突与非法数字、越界路径。
- `tests/feishu-assistant.spec.ts`：真实来源入口的仅所有者查询、原线程范围、报告导出、权限撤销、控制版本、重放及查询不唤醒。
- `tests/feishu-mail.spec.ts`：飞书／163 所有者与账号版本绑定、固定版本预览与确认、取消、暂停／撤权、服务切换和未知结果不重发；使用模拟邮箱接口。
- `tests/smtp-mail.spec.ts`：真实 Python 桥接配合模拟 SMTP，验证 TLS 配置、凭据文件权限、失败不覆盖、MIME、本人收件人、提交去重与错误脱敏。

自动化测试不向真实飞书发送消息，也不调用付费模型；实际联调证据单独记录。
