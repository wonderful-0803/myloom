# 跨设备接续：私人同步空间与设备配对

实现日期：2026-11-06。本轮范围是同一所有者、两台或多台获邀设备、指定项目的 Codex 可见文字讨论。读取历史、上传和 AI 检索分别授权，不控制另一台设备的 Agent，不复制 Codex 登录凭据，也不改写原生会话数据库。

## 已接入的工作路径

本机 Loom 的“跨设备”页面可创建私人空间、以一次性邀请加入、使用恢复凭据重新建立管理设备、创建项目、授权本机采集、授权本机 AI 读取、查看同步会话、保存方案和修改理由、撤销设备及删除服务器项目记录。

两端访问同一个独立同步服务。源设备成功上传后可以关机；另一端从服务的持久副本读取。源设备未上传的记录无法从离线机器补回。同步服务必须在线，当前不提供服务离线时仍可访问的历史缓存。连接设置和历史分页检查点留在本机受保护的 Runtime 目录中。两端需先能进入现有 Loom 个人工作空间（本机飞书唯一所有者已配置）；设备配对不替代现有首次配置向导。

用户创建/加入空间时不会读取任何历史，也不会默认开启同步。每个项目需要指定本机绝对路径并确认持续读取及上传用途；目录精确匹配，不递归扩大到父目录或其他项目。该授权独立于既有“按天查看 Codex”和日报委托。

启用后每30秒检查一次，支持立即同步。目录扫描包含当前与归档的交互会话，排除子 Agent、临时及自动执行来源；读取只通过已安装 Codex 的只读 App Server 接口。每轮至多扫描两组各10页目录、20个项目会话；每个会话读取最新页及最多两页旧记录，后台增量补齐历史。覆盖限制会随会话记录保存，达到目录上限时明确提示。没有时间的记录不推断时间。

仅同步用户与助手的可见文字。系统/开发者消息、工具调用结果、内部推理和附件正文不纳入同步；自动环境、浏览器和页面状态不作为用户讨论。单条文字超过40000字符会明确标注截断。每次上传上限2MB；每个会话最多20000条文字或200万字符，超过后停止并显示错误，不宣称完成。项目最多保存500份或100万字符的本人方案记录。

消息按来源设备、原生会话和消息标识去重；对已有消息的更新形成新的不可变批次版本。已上传文字不会因后续批次只含增量而丢失。分页检查点只有在本轮上传全部取得回执后前进；失败重试不会重复追加。成功时间代表服务端已提交持久数据，不代表转写、附件或被排除内容也已同步。

上传回执绑定原始批次哈希；回执不匹配时不前进检查点。Windows 的 Codex 读取器直接运行原生可执行文件或 npm 的 JS 入口，不经 Shell 转发参数；安装版本0.160.1已在空的隔离 `CODEX_HOME` 验证初始化与空列表，没有读取用户真实历史。

## 部署同步服务

服务与原有本机管理接口分离。只暴露配对、项目和数据同步能力，没有 Shell、工具执行或本机管理代理。默认仅监听回环地址，在其前方配置企业允许的 HTTPS 反向代理；两台设备必须均获准访问该服务。

先在仓库根目录安装依赖并编译：

```powershell
pnpm install --frozen-lockfile
pnpm build
```

准备独立的数据目录、随机初始化凭据文件，并限制其文件权限。以下是 Windows 示例，路径按部署环境修改；不要把凭据提交到仓库：

```powershell
New-Item -ItemType Directory -Path C:/LoomSync -Force
node -e "require('fs').writeFileSync('C:/LoomSync/bootstrap.key', require('crypto').randomBytes(32).toString('base64url'), {mode:0o600,flag:'wx'})"
$syncPrincipal = [System.Security.Principal.WindowsIdentity]::GetCurrent().Name
icacls C:/LoomSync /inheritance:r /grant:r "${syncPrincipal}:(OI)(CI)F"
$env:LOOM_SYNC_BOOTSTRAP_FILE = 'C:/LoomSync/bootstrap.key'
$env:LOOM_SYNC_DATA = 'C:/LoomSync/data'
$env:LOOM_SYNC_PORT = '7421'
pnpm sync:server
```

启动日志不打印初始化凭据。它由服务管理员通过可信方式提供给首次创建空间的人；不要放在 URL 中。此凭据具有创建空间的权限，不是某个设备的登录凭据。Linux 使用仅服务账号可访问的目录和0600凭据文件。生产服务由公司现有进程管理/容器基础设施托管，应用本身不安装系统服务。

`LOOM_SYNC_HOST` 默认为 `127.0.0.1`；端口默认7421。反向代理只转发此独立服务，不转发现有 `/orchestrator` 管理服务。连接器拒绝重定向，不跟随跳转携带凭据；明文 HTTP 仅接受 localhost/回环联调。

## 首次配对与项目授权

1. 家里 Loom 打开“跨设备”，选“创建私人空间”，输入 HTTPS 服务地址、设备名称及管理员提供的初始化凭据。
2. 保存仅本次显示的恢复凭据和空间标识。恢复凭据可建立新管理设备，应独立安全保存；此版本没有邮箱找回和恢复凭据轮换界面。
3. 创建项目，指定家里机器上的精确 Codex 项目路径，勾选读取/上传许可并保存，再开启自动同步。
4. 为当前项目签发一次性邀请。邀请仅允许指定项目，默认24小时有效；公司设备可在源机器离线时凭事先签发的邀请加入。
5. 公司 Loom 选择“加入已有空间”，输入相同服务地址、独立设备名称和邀请。每台设备获得独立随机凭据。公司路径可与家里不同，也可以只读取历史而不配置本机上传。
6. 需要公司继续形成方案时，为同一个项目绑定公司本机路径并授权采集。新会话保留独立来源身份，统一归属这个项目。

服务端每次核验设备和项目权限。邀请只能消费一次；签发设备已撤销后，未使用邀请也失效。只有空间管理设备可创建项目、发邀请及撤销设备；普通配对设备仅能读写获邀项目。服务端保存凭据哈希，配对、恢复入口限流；不接受浏览器跨站请求。

本机设备凭据存于 Runtime 的 `device-sync/local.sqlite`，不在普通状态 API、同步正文、MCP 配置、模型输入或日志中返回。该文件使用0600，父目录0700；Windows 需要使用桌面 Runtime 已有的私有目录 ACL，独立部署者也需配置对应 ACL。此版本没有接入系统钥匙串，不声称凭据文件加密。

## 让 AI 继续讨论

“允许本机 AI 读取此项目”是另一项明确授权。仅开启上传不会允许 AI 召回其他项目。页面可查看/复制带来源的上下文，也可显示当前实例的 Codex MCP 配置。

将页面生成的 `[mcp_servers.loom_context]` 配置合并到本机 Codex 配置后重新连接 MCP。入口执行编译后的 `lib/sync-mcp.js`，只访问本机回环 Loom API，不持有远端设备凭据，也不连接来源电脑。

可让当前 AI “从 Loom 接着讨论退款项目”。工具提供：

- `loom_list_projects`：仅列出本机明确允许 AI 使用的项目。
- `loom_get_context`：读取当前项目方案、修改理由、未决问题、分支提示及最近的原始文字来源。
- `loom_read_session`：按来源设备和原生会话分页核对原文。
- `loom_read_note`：核对某份本人保存的完整方案及修改理由。

MCP 使用官方 TypeScript SDK 2.4.0 的 stdio 入口，兼容旧握手与现代协议。全部工具只读，不启动/接管 Codex；历史正文不构成本轮操作授权。MCP 连接依赖当前电脑的 Loom 运行，不能仅安装配置而关闭本地 Runtime。这里是工具接入，不承诺在每个原生新聊天中自动注入背景，也没有自动安装/修改用户现有 Codex 配置。

当前方案和理由由本人显式保存，支持前序方案引用。A 可以演变为 B；并行形成 B、C 时保留分支并提示核对，不按时间自动覆盖。没有说明的理由保持未明确。首版不自动用模型提炼或认定业务决定。上下文输出有60000字符预算，保留来源标识；更早文字和完整方案需通过相应工具按需读取。

## 暂停、删除与信任边界

- 自动同步、单个项目采集可分别暂停。全局后台暂停也阻止新同步轮次；在途操作返回后复核授权，旧检查点不前进。已经被服务器接收的请求不能宣称撤回。
- AI 项目授权可独立撤销；后续查询在本机和服务端均检查。设备撤销后，后续远端读取/写入被拒绝。本机收到401后关闭该连接的自动同步和 AI 授权。
- 断开本机移除本地连接和采集检查点，服务器历史保留。服务器项目删除会移除该项目的当前会话、批次版本和方案记录；原设备上的原生会话及已经下载/复制的内容不能远程收回。
- 服务器记录默认持续保留至本人删除项目。SQLite/WAL 与备份中的物理数据清除需按公司存储策略处理；本接口不声称安全擦除历史磁盘块。
- 原生会话的删除或回滚不会自动删除服务器历史；同步空间中的删除需显式操作。自动识别撤回与判断失效没有在本轮引入。
- 传输依赖 HTTPS，服务及数据目录必须由可信操作者管理。当前不是端到端加密：服务管理员和获准的服务端处理能接触明文。不同账号/租户的团队身份、企业SSO、组织审批和远程执行没有在本轮引入。
- 已获授权的共享空间是召回边界。模型账号相同不替代公司资料跨设备授权；不要把公司项目加入不获准的个人空间。

## 验证证据与范围

`tests/device-sync.spec.ts` 使用真实 HTTP、持久 SQLite 和两个独立连接器，验证 A→来源离线→B与理由→同步服务重启→A、重复上传、跨空间/项目拒绝、一次性邀请、恢复、设备撤销、AI 独立授权、分支、采集中撤权、TLS边界及历史补齐。Codex 响应为合成数据，没有读取用户历史或调用付费模型。

`tests/device-sync-api.spec.ts` 验证真实 Runtime 的本机路由、默认关闭状态、MCP配置与非法参数；`loom/src/client/live/DeviceSync.test.tsx` 验证前端默认配对、采集同意和 AI 独立授权入口。`scripts/smoke-sync.mjs` 在编译后启动真实 MCP 子进程，检查工具列表、来源设备离线后的 A/B 上下文，以及撤销 AI 授权后拒绝召回。

```powershell
pnpm typecheck
pnpm exec vitest run tests/device-sync.spec.ts tests/device-sync-api.spec.ts
pnpm check:loom
pnpm build
pnpm sync:smoke
pnpm sync:smoke:codex
```

两台真实用户电脑、实际 Codex 历史、公司 HTTPS/网络及文件 ACL 部署仍需配置后验收。本轮没有部署外网服务、没有启用用户历史上传，也没有修改原生 Codex 会话数据。

本轮 Windows 检查记录：42项相关后端/文档回归、前端6项测试、两端类型检查、前后端构建、编译后 MCP 联调和真实 CLI 的空目录只读连接均通过。全量 `pnpm check` 执行出现 Unix命令缺失及Unix文件权限语义等失败，未声称全仓检查全绿；本次补齐了类注释和架构索引，并修复文档验证器的 Windows 路径/CRLF 兼容。

协议依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[MCP 官方 stdio SDK](https://ts.sdk.modelcontextprotocol.io/v2/serving/stdio)。
