# 飞书助手：已接通的查询与控制

更新：2026-11-03。继续使用现有“个人助手机器人”，不依赖待审批的新应用或飞书工作台。实现位于 `src/app/feishu-assistant.ts` 和 `src/app/feishu-mail.ts`。实际验收见 [联调记录](PERSONAL_ACCEPTANCE.md)。

每条消息只执行一条指令；多行命令或多余参数会被拒绝。确认邮件须使用当前卡片或预览返回的完整指令。卡片需要应用已订阅 `card.action.trigger`；本轮核查原应用仍在发布审核中、回调列表为空且无法添加，所以当前部署继续使用文字入口，不显示无效按钮。

## 本轮新增：引用消息、版本与静默草稿

私聊无需每次点“回复”：查看具体任务、单一草稿箱或某份产物后，助手会保存当前选择 30 分钟，按本人及私聊分别绑定。随后可直接发送“看看进展”“暂停这个任务”“编辑这份草稿”“改稿为：…”“导出”或“把这版发到我邮箱”（仅预览）。多个候选的总览会清除选择；新工作请求也不继续套用旧选择。显式回复旧消息时优先使用旧消息的版本，不升级为当前版本。助手私聊回复留在主会话；群内仍限定原任务线程，产物正文和邮件只在私聊提供。

| 命令 | 行为 |
| --- | --- |
| `/助手 版本 任务ID` | 查看已保存的正文版本及时间、作者、摘要哈希 |
| `/助手 来源 任务ID` | 查看该正文版本的来源消息 ID 与 SHA256 |
| `/助手 产物 任务ID v1` | 读取获授权的历史版本 |
| `/助手 导出 任务ID v1` | 导出指定版本的正文 TXT |
| `/助手 编辑 任务ID` | 在本人已接管且在途操作归零后，打开指定版本的编辑入口 |
| 打开编辑后直接发送 `改稿为：` 加完整正文 | 按上次显示的版本保存新稿；旧版保留，不原地覆盖 |
| `/助手 草稿箱` 或“草稿箱” | 私聊查看静默草稿，查询本身不调用模型 |
| `/助手 草稿 草稿ID` | 查看本地草稿正文 |
| `/助手 编辑草稿 草稿ID` | 编辑本地草稿；没有 Worker，无需任务交接 |
| `/助手 确认草稿 草稿ID` | 确认当前草稿版本；后续改稿需要重新确认，不触发发送 |
| `/助手 忽略草稿 草稿ID` | 取消排队／正在起草的结果，或忽略已有草稿 |
| `/助手 导出草稿 草稿ID` | 导出草稿版本正文 |

每次 Worker 的 progress/ready 报告保存为新的正文版本；旧任务在首次查看时导入现有持久报告，不补造已经丢失的历史。版本记录正文、作者、源消息及哈希、当前要求指纹。人工编辑后，Worker 必须读取 `orchestrator_artifact` 并提交相符的 `artifact_version` 才能继续发布。邮件许可绑定正文版本、哈希和要求指纹，除此之外仍检查任务、控制状态与邮箱身份。

这是一人串行改稿与冲突保护，不是多人实时合并。来源权限检查覆盖消息、正文预览、版本历史、导出与邮件；外部网页引用、计算文件等仍由原报告及工作目录快照提供证据。当前版本库登记的是报告正文，尚不提供任意工作目录文件下载、完整文件产物索引或 OS 沙箱。

受控静默起草为独立配置，不把 observe 全局切为 auto。仅在 `draftsEnabled: true`、`draftChats` 中的群已配置接收全部消息、本人未 @ 的请求通过 `office-summary` 观察规则后，起草自带记录的工作总结／纪要。最多 6000 输入字符、900 输出 token、30 秒，单并发；`draftDailyLimit` 默认为上海时区每日 3 次，启动前持久计数，失败也计入预算。线程新要求、权限或配置撤销会中止／丢弃旧结果；重启不重放进行中的模型调用。

模型调用没有工具、其他会话、文件或网络读取能力，不创建 Worker，不回复群，不自动发信。含外链、检索或附件的需求保持普通任务流程。群无 @ 事件是否真正到达仍取决于飞书权限和实际订阅，不能用“没回复”作为通过证据。

也可私聊主动试用同一受控起草链路，每条消息如下：

```text
/助手 起草
工作总结：仅根据以下虚构记录，整理已完成、阻碍、下一步。
R1：已完成访谈整理。
R2：明天复核渠道数据。
```

机器人返回入箱记录后，稍后发送“草稿箱”。只有本人提出该请求，才允许此次模型调用；普通查询不会起草。旧消息不会触发新的起草或改稿。卡片可用后，同一后端提供任务选择、状态控制、邮件预览／确认、草稿确认／忽略及短正文编辑表单；实际操作者、原卡片／会话、有效期、版本与单次许可都在后端核验。

## 私聊取回任务与报告

直接私聊机器人发送“我的任务”，获取自己的任务 ID。每页最多 5 项；更多任务用 `/助手 任务 2`。以下命令中的 `任务ID` 替换为列表返回的真实 ID：

| 命令 | 当前行为 |
| --- | --- |
| `/助手` | 返回帮助 |
| `/助手 状态 任务ID` | 查询任务是否结束、控制权和在途操作 |
| `/助手 产物 任务ID` | 查看最近一次已保存报告的正文预览 |
| `/助手 导出 任务ID` | 将完整报告作为真实 `result.txt` 附件回复 |
| `/助手 暂停 任务ID` | 阻止后续受管操作，等待在途操作结束 |
| `/助手 接管 任务ID` | 发起控制权交接，完成后显示“你已接管” |

也可使用“我的产物”“查看工作总结进展”等有限的明确查询表达。唯一的任务标题片段或至少 6 位的唯一 ID 前缀可定位任务；存在歧义时须复制完整 ID。查询直接读取持久记录，不调用模型，不新建、重启或暂停任务。

当前导出的是**已保存报告正文**，不是任务目录中的任意文件。CSV 计算快照、XLSX、DOCX 等原生文件的索引与取回仍待实现。阶段报告与已完成结果会明确区分；查询不会为了生成新结果而唤醒 Worker。

## 原线程介入

在群内原任务线程发送 `/助手 状态`、`/助手 暂停` 或 `/助手 接管`，可省略 ID。旧应用如仅收到 @ 消息，请用飞书的 @ 功能选中机器人再发送指令。另起群消息或其他线程不能通过填写 ID 控制这个任务。

暂停完成后，状态回复提供带当前版本的 `/助手 继续 任务ID rN`；接管完成后提供 `/助手 交还 任务ID rN`。复制最新回复中的完整指令即可。旧版本、过期控制消息和重放消息不会解除新的暂停。查看状态不改变控制权；继续已结束的任务也不会重启它。

群内只能查看或控制该原线程的任务。任务总览、报告正文、导出和邮件操作只在所有者私聊提供。其他成员不能通过声称“我是所有者”、转发消息或写入任务 ID 获得权限。

控制范围为 Harness 管理的工具、后台作业和交付队列，不等同于 OS 隔离或任意设备进程接管。结果不明的外部操作仍需从本机管理页核查，不能把取消请求当成撤销成功。正文编辑已接入版本库，卡片按钮的真实使用受上文平台回调限制。

## 邮件交付：当前使用 163

用户选择先用 163 个人邮箱验证。163 的 TLS 连接、SMTP 登录及本机配置与飞书所有者／应用绑定均已实测通过；企业邮箱已从助手当前接入中关闭。机器人内 163 预览、本人确认发送、SMTP 接收均已读回核验，用户已确认实际收到邮件，详见联调记录。

首次配置在自己的终端运行 `python3 scripts/personal-mail configure --owner 真实飞书open_id --app-id 真实应用ID`。命令提示输入 @163.com 地址和客户端授权码，授权码不回显；只验证登录，不发送测试邮件。授权码从网页版邮箱的 SMTP 服务设置生成，可参考[客户端授权码获取说明](https://consumer.huawei.com/cn/support/content/zh-cn15872099/)。使用 `smtp.163.com:465`、TLS 证书校验，不能使用明文降级。

凭据保存在本机 `~/.config/superagent/163-mail.json`（目录 700、文件 600），通过 `scripts/personal-mail` 读取，不把授权码放入来源配置、聊天、模型输入或命令参数。配置先验证再原子替换，失败保留原配置；每次配置生成新的账号版本，使旧预览失效。这是当前 OS 用户下的受控代理，不是独立凭据沙箱。

来源高级配置选择 `mailProvider: 163`，`smtpCli` 指向本机 `scripts/personal-mail` 的绝对路径。`mailCli` 保持空；IM 仍使用原来的 bot-only CLI。

1. 私聊 `/助手 邮箱`，核对当前连接的真实 163 邮箱；桥接命令重新验证 SMTP 登录，不读取收件箱。
2. 私聊 `/助手 邮件 任务ID`，预览已完成任务的固定报告、收件人、主题和摘要。此时只保存本地预览，不发送。
3. 认可后发送预览返回的 `/助手 确认邮件 令牌`，由当前所有者提交该固定版本。
4. 提交前可 `/助手 取消邮件 令牌`；提交开始后如实显示在途或结果不明，不宣称已经撤销。
5. `/助手 邮件状态 令牌` 读取持久提交记录。SMTP 接收成功显示“服务器已接收”，最终送达在实际收件箱核对；不把 SMTP 接收当作已送达回执，也不自动读取邮箱。

首版仅给绑定的本人邮箱发送，不开放任意收件人。单次预览 10 分钟内有效；任务、控制状态、邮件服务或账号版本变化需重新预览。发送前重新核验任务、所有者、资源范围和目的地；暂停／接管阻止后续操作，已开始的 SMTP 请求等待实际结果。163 同时附上已登记版本的报告文本，拒绝任意设备文件。

每次发送使用稳定 Message-ID。桥接在网络调用前持久记录结果未知，接收成功后先保存 SMTP 接收记录再返回；相同 Message-ID 不重复提交，响应丢失时只核查记录和实际邮箱，不自动重发。新建另一份预览仍是另一次显式发送许可，不代表跨所有预览的全局去重。

识别到“工作总结”“纪要”本身不获得发信许可。Loom 的“产物交付”新增本人明确保存的常驻邮箱授权：核对绑定地址并保存后，后续完成定稿可自动发送，无需逐次预览；换绑、撤权、改稿或暂停使旧许可失效。默认方式为飞书报告附件，可选只在 Loom 保留；任务可覆盖默认设置。历史结果不批量补发，详情可显式投递最新版。当前附件仅为已登记的 `.md`／`.txt` 报告快照；完整办公文件索引、按内容筛选的邮箱规则及其他收件人仍待实现。详见 [Loom 交付方式](LOOM_SETUP.md)。

飞书企业邮箱适配保留，但本轮不继续补权限或验证发送。此前只取得邮箱地址读取和草稿授权；若以后恢复，还需发送及投递状态权限。邮件服务切换会使旧发送许可不可用。

## 当前证据与边界

- 私聊“我的任务”、报告预览和真实 `result.txt` 已由操作者收取，并通过飞书消息 API 读回；任务数量保持不变。
- 暂停、接管、继续与交还的文字入口已部署。原群线程暂停／状态查询／继续已通过实际指令与回执验证；飞书接管／交还实测仍待补充。
- 自动化测试覆盖真实来源入口的身份与任务范围、查询不唤醒、权限撤销、版本冲突、重复消息及发送结果不明；异常与恢复测试使用模拟接口；163 单次正常交付另有实际飞书回执、SMTP 记录与用户收件确认，不能据此声称异常场景已全部实测。
- 当前仅单个所有者与指定测试群；基础模式已按用户要求切为 `auto`，模型和原机器人保持既有接入。正文版本、串行改稿及有预算的起草已实现，卡片真实回调待平台解锁与验收；完整文件产物索引、多人实时编辑、按内容筛选的邮箱规则与推广隔离仍待后续实现。
