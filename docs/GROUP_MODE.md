# Loom 群内共享模式

2026-11-06 用户确认：保留同一套 Loom 产品和同一 Runtime，新增可选的“群内共享”运行模式，不另建共享助手产品。当前个人模式继续保留。

2026-11-12 范围补充：同一机器人可服务多个**独立授权的群工作空间**。每群仍按本文的主人、上下文、接管和交付边界工作；通过公司多群启动器与新管理入口实现，不在个人页面自动开启。操作、部署、限制和验证见 [多群工作空间](MULTI_GROUP.md)。下文的“一个实例一个群”描述原单群入口。

## 单群模式的既有实现

一个实例同一时间服务一个指定共享群；管理者从实际群成员中选择 1–20 位“主人”，自己保留在名单内。主人可在群内明确发起任务；开启基础规则 auto 或群委托 auto 后，也可静默识别其未 @ 的需求。观察模式仍不自动执行。其他人发言只保存为群上下文，不接单、不唤醒已有 Worker、不接受控制指令。其他群、私聊和其他来源不进入共享实例。

名单勾选后须保存才生效；每一位已保存的主人均可发起、补充和控制本群任务。界面的“管理者”标记表示维护本机配置的身份，他也属于主人且必须保留在名单内，不限制其他已授权主人发起任务。设置页分别显示当前已生效的名单与编辑中的勾选项。选择多位主人不会让每句话都开工，仍按当前规则、处理模式及有效需求判断接单。

复用既有 Engine、Harness Worker、任务页、进展、控制状态、不可变报告版本和交付队列。共享主人可以查询同群任务，在原线程补充要求、暂停、接管、按明确版本改稿及交还；正文保留任务原发起者与实际改稿者。控制消息仍需满足实际操作者、群范围、时效和 revision 校验。多人编辑采用串行接管及版本冲突检查，不实现实时合并。

定稿固定交付原群消息线程的报告文件。投递记录保存版本、哈希、状态和消息 ID；暂停、改稿、来源或名单变更会阻止不再有效的排队交付。同一版本不重复投递，结果不明不自动重发。当前不提供共享邮箱交付或将共享结果转个人私聊。

## 在同一界面配置

1. 先按 [现有部署文档](006-deployment.md) / [飞书初始化](PERSONAL_SETUP.md) 准备一个独立实例：关闭 GitHub、启用唯一管理者与 ownerOnly、设置机器人及精确监听群；群消息权限由飞书企业管理员批准。
2. 打开 Loom → 设置 → **运行模式**，选择 **群内共享**，选择现有已授权监听群。
3. 点击 **读取群成员，选择主人**，逐个勾选。读取失败时不能保存；后台保存时重新读取成员，不信任浏览器提交的姓名和身份声明。成员同步不会自动把全群变成主人。
4. 保存模式。切换个人／共享模式或切换工作群会更换调度会话并重启 Runtime，防止复用个人调度上下文；仅调整同群名单不更换整个工作空间。原有任务和设置保留，未完成且失去授权的任务持久暂停，重新授权不自动解除人工暂停。
5. 在 **委托与自主处理** 按需选择 auto / observe，或为当前群新建持续委托。已有个人委托不自动转成共享委托。

模式配置保存在版本化 `policy.sources.feishu.workspace`，原来的唯一管理者 `allowed` 不扩成全群名单。共享主人单独保存。API：`GET /orchestrator/api/loom/workspace`，`GET .../workspace/members?chatId=...`，`PUT .../workspace`；请求沿用现有本机同源管理校验，不接受请求者自行指定操作身份。

工作空间附带独立 `spaceId` 和启用时间，来源入站时由 Runtime 标记。旧个人任务不会因为切换模式被公开；关闭后再启用会生成新空间，旧消息不自动重放为任务。普通群讨论在 SQLite 持久保存，按空间索引分页召回；Worker 使用 `orchestrator_read(resource="group-context")`，实际读取的消息登记到报告来源，保留 SHA256。这里保存原始讨论，不自动把意见升级成已确认决定。当前没有自动过期清理，部署前应确定公司的留存期限；管理员通过受控备份和实例数据管理处理，不能宣称已有企业级删除管理。

## 已落地的权限边界

- 入站、任务控制、正文读取、历史版本、导出、Worker 读取与交付复核当前空间和主人授权；移除主人后不能继续其任务，需由管理者重新确认授权及恢复方式。
- 私聊、个人邮箱、Codex 历史／日报、跨设备私人同步、个人草稿在共享模式下不可用。已经授权的同步后台也无法通过共享身份继续获取个人 owner。
- 共享模式的 Router 和 Worker 仅使用受控群资料／任务工具，不开放通用 Shell、本机文件、CLI、子 Agent 或未经授权的资源连接器。不可用的继承工具不向模型展示；Worker 将完整正文与输出选项提交给宿主，由固定生成器制作文本或真实 Word 附件，`artifact_file` 在共享模式直接拒绝。Word 文件按版本保存字节与哈希，下载及投递复核来源；详见 [任务文档](DOCUMENT_ARTIFACTS.md)。模型不能修改主人、持续授权或资源范围。限制是应用工具边界，不替代公司服务器的 OS 账户、容器和网络隔离。
- 群消息正文和其他成员发言是资料，不能凭内容增加主人、开启工具或改变交付目的地。共享来源混入其他群、私聊或个人数据后，报告读取与交付被拒绝。
- 全部主人是该群共享任务的共同操作者。名单变化会使未发送的旧交付授权失效；已经发送的消息与下载文件无法保证撤回。群成员增减不会自动改变主人名单；管理员须同步撤销不再适用的主人授权。

## 公司服务器部署

沿用同一代码、构建与 Harness profile，在公司服务器准备专用 OS 账号、独立的 Harness home、状态目录和机器人配置。不要上传个人实例数据库、用户令牌或邮箱凭据。机器人凭据只允许 bot 身份，模型采用公司批准的服务。

前置安装和启动复用 [006 Deployment](006-deployment.md)，生命周期继续使用 `scripts/dsh-superagent`，通过该脚本的 `--help` 指定公司 profile、URL 与日志。保持服务监听 `127.0.0.1`；管理员通过 SSH 本地端口转发管理。例如服务器使用默认端口时：

```sh
ssh -N -L 3082:127.0.0.1:3082 company-loom-server
```

随后在管理员电脑打开 `http://127.0.0.1:3082/orchestrator/loom/`。本地端口须未被其他 Loom 占用；Host／Origin 校验要求两端端口一致，需要其他端口时同时调整服务器 profile 与转发端口，不删除来源校验。

群成员直接使用飞书，无需桌面安装。当前 Loom 管理页仍是本机管理员入口，不是面向所有主人的企业网页登录服务；飞书工作台／SSO 入口需后续补齐身份网关，不能直接反代整个 Harness 或复用免登录演示隧道。飞书消息使用既有长连接消费者，服务器需能访问飞书与批准的模型服务；不要为同一机器人再运行第二个消费者。2026-11-06 已在用户提供的 Ubuntu ARM64 一体机部署独立账号、profile 和 systemd 服务，真实模型工具调用与异常恢复已验证；随后补齐新应用的应用身份成员权限，单主人真实群任务、连续改稿、附件及接管持久化已通过，详见 [服务器部署与验收](SERVER_DEPLOYMENT.md)。
