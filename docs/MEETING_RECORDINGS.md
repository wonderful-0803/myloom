# 群录音与会议纪要

2026-11-06：同一 Loom 的共享群模式新增录音专用持续委托。按用户最新选择，试点优先使用百炼 `qwen-audio-3.1-asr-flash-filetrans`，不要求安装本地语音模型。本地 SenseVoice 实现保留为可选连接器，云端失败不会自动切换服务。

## 使用流程

在「委托 → 新建委托 → 录音会议纪要」选择当前共享群，核对实际 ASR 服务、资料用途与交付范围后勾选授权。该群同一时间最多启用一条录音委托；普通文字委托不会获得音频访问权限。

主人新发语音或支持的录音附件时，Loom 用机器人身份读取原消息，核验实际群、发件人、资源键和消息状态。只有原生 audio 消息或有音频扩展名的原生 file 消息会进入录音流程；正文伪造的文件键不授予访问权。

仅发送录音时，机器人在原话题询问一次“需要把它转成会议纪要吗”，说明录音将提交到哪家服务。当前任何一位已授权主人可在该原话题回复“需要”或“生成纪要”；回复“取消”可终止。若一个话题有多份录音，需回复对应询问，不能凭一句确认猜测文件。确认 24 小时有效，不重放委托启用前的历史文件。

确认后建立普通 Loom 任务，使用现有进展、暂停、接管和版本化报告。受控转写工具绑定本任务已确认的录音，不接受任意路径、URL、文件键或其他群。转写保留时间戳；匿名说话人编号不能认定真实姓名。Worker 必须分页读完整份转写后才能提交定稿，纪要的决定、负责人和截止时间没有明确依据时标待确认。报告固定发回原群线程。

文字转写稿仍走既有文字任务规则；单纯分享文字不自动视为要求生成纪要。

## 服务配置

百炼模式需要 Node、`ffmpeg` / `ffprobe`，不需要本地 ASR 模型。由服务器管理员配置以下环境变量，不在聊天或网页中粘贴密钥：

```ini
LOOM_ASR_PROVIDER=bailian
LOOM_ASR_MODEL=qwen-audio-3.1-asr-flash-filetrans
LOOM_ASR_API_KEY_FILE=/var/lib/loom/asr.key
LOOM_ASR_ENDPOINT=https://dashscope.aliyuncs.com/api/v1
```

凭据文件归服务账号所有、权限 0600，复用本次已验证的百炼账号。端点只接受已支持的百炼 HTTPS 地址。原线程确认及委托授权绑定实际服务与模型；服务或模型变化会使旧确认失效，不能在未重新确认的情况下改用另一服务。

试点使用官方 SDK 对应的私有临时上传协议：上传策略为 private；百炼 API Key 只发往配置中的百炼 API，上传和结果下载不携带该 Key。OSS 主机和结果 URL 限制为供应商 HTTPS 域名，不跟随重定向。临时 URL 按官方 48 小时有效期管理，不宣称已从供应商立即删除音频。正式企业部署需换成公司受管私有 OSS，明确存储清理、数据处理与留存策略；官方也不建议临时上传空间用于生产或高并发。

服务重启或工具重试时，有实际 task_id 的任务继续查询；提交结果不明时不自动再提交。暂停、撤权会停止本机后续操作和结果发布，已经提交的云端任务可能继续计算；不能宣称已取消云端计算或撤回已经发出的报告。

本地可选模式设 `LOOM_ASR_PROVIDER=local`、`LOOM_ASR_PYTHON` 和 `LOOM_ASR_MODEL_DIR`；模型目录需要 `model.int8.onnx`、`tokens.txt`、`silero_vad.onnx`，使用 sherpa-onnx 2.0.1 与 numpy 2.2.6。模型和运行时独立部署，不打入用户安装包。

## 边界与验收

单份录音不超过 80 MB / 2 小时；本群滚动 24 小时最多创建 6 个录音任务，单次转写墙钟上限 30 分钟。多声道音频在本机合并后送入识别，避免只取第一声道遗漏发言。解码拒绝网络协议及播放列表格式，不提供通用文件工具。超限、空白或识别不完整时报告受阻，不截断后冒充完整纪要。

临时音频正常完成或失败后删除，独占实例启动时清理本连接器遗留的私有临时目录；转写、来源哈希和同意记录持久保存。转写读取、提交定稿与发送报告前复核原消息；来源失效、移除主人或暂停委托后阻止后续使用。已有本地管理界面及备份的留存权限仍需公司管理员管理，不构成完整企业资料删除网关。

实现：`src/app/meetings.ts`、`src/asr-bailian.ts`、`src/audio.ts`、`src/meeting-delegation.ts`，复用 `delegations.ts`、`resources.ts`、`sessions.ts`、`artifacts.ts`、`result-delivery.ts` 及 Loom 委托页。

隔离测试：`tests/meetings.spec.ts`、`tests/asr-bailian.spec.ts`、`loom/src/client/live/MeetingDelegation.test.tsx`。覆盖同意、主人身份、群／原线程、重复消息、取消、过期、撤权、暂停、来源变更、正文分页门禁、云任务接续与密钥隔离。测试中的飞书和模型外部操作使用替身，不等于真实群验收。

真实服务验证：一体机已用实际百炼凭据通过 private 上传、异步 task_id、轮询和结果读回，5.592 秒官方中文音频转写为“开放时间早上9点至下午5点。”，含时间戳与匿名说话人。单独本地 SenseVoice 也识别同一示例，但未启用于公司服务。该示例只验证服务连接，后续真实群验收单独记录。

实际公司服务已于 16:50 升级并启用「群录音会议纪要」，仅 Harness研究小小组，保留用户选定的四位主人。委托页已读回服务配置与生效回执，部署版本、备份及证据见 [SERVER_DEPLOYMENT.md](SERVER_DEPLOYMENT.md)。

参考：[百炼 Filetrans 官方 API](https://help.aliyun.com/zh/model-studio/qwen-audio-asr-filetrans-http-api)、已查阅的官方 dashscope 2.0.3 SDK `resources/_oss_upload.py`；[可选本地识别 API](https://k2-fsa.github.io/sherpa/onnx/sense-voice/python-api.html)。
