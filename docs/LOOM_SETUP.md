# Loom 与个人飞书助手

2026-11-04 将提供的 `loom-ui-refresh-src.tar.gz` 解压到本仓库的 `loom/` 和 `loom-sandbox/`。保留原有界面与独立演示代码，新增真实个人工作空间入口。

## 运行

现有 Superagent 服务仍是唯一的飞书监听器、任务执行器和状态库。构建 Loom 后，通过同一个回环服务打开：

```text
http://127.0.0.1:3082/orchestrator/loom/
```

首次安装和构建：

```sh
pnpm --dir loom install --ignore-scripts
pnpm build:loom
pnpm build
scripts/personal-superagent restart
```

真实入口只使用 Loom 构建出的 React 界面，不启动其演示 Express 服务，不读取或新建 `loom.db`，不需要安装 SQLite 原生扩展。`loom-sandbox/` 仅供原始演示使用。模型、飞书与邮箱凭据继续由现有本机配置及 CLI 代理持有，Loom 不接收或复制密钥。

## 已接入

- 工作概览、任务、事件收件箱与现有飞书记录同步；每 3 秒刷新可见页面，重新聚焦后刷新。读取不启动 Worker，不进行模型评估。
- 任务详情支持暂停、继续、接管和交还；复用受管在途操作及控制版本检查。接管进行中不开放编辑，不能将请求已接收视为移交已完成。
- 草稿箱显示受控静默草稿，可查看、确认、忽略、修改和导出。确认不会向群或邮箱投递，取消正在运行的草稿仍调用原有取消机制。
- 交付物显示保存的报告；支持正文编辑、旧版本查看、作者、来源消息及 SHA256、TXT 导出。编辑任务报告须先接管，草稿可以直接编辑；保存固定基准版本，冲突返回 409，保留本人输入。来自 Loom 的本人版本标为 `editedVia: loom`，不伪造飞书消息来源。
- 完成任务的报告可准备邮件预览，展示本人收件人、主题、固定版本及正文，由用户点击确认才调用原有发送服务；可取消许可和查询状态。提交结果不明时不自动重发。
- 连接页展示当前机器人、模型、监听群、卡片开关和服务状态，按需验证邮箱；不提供重复配置密钥或扩大权限的表单。
- “持续委托”可创建、编辑、启用和暂停常驻目标，查看对应任务和交付物。它直接保存为原生版本化策略规则；每条委托单独选择自动执行／仅观察，不切换其他规则的模式。
- “事件收件箱”保留原接单判断，同时关联当前仍获授权的任务，显示执行／排队／控制状态，并直接打开既有实时进展和交付物。概览、事件页与任务页使用同一快照；每 3 秒单请求刷新，切页、焦点与嵌入标签可见性变化也触发更新，慢请求不会被下一轮刷新丢弃，10 秒请求超时后明确显示旧数据与自动重试。
- “自主处理”提供基础规则的关闭／观察／自动执行模式，并支持逐条启停已有基础规则。模式入口在概览、持续委托与连接设置页；事件页展示当前模式和历史决策的区别。

新需求与任务后续要求仍从现有飞书入口进入。Loom 提供查看、编辑及控制，不把浏览器输入伪装成飞书用户消息。飞书原线程、机器人私聊和 Loom 共用同一份记录；已经实现的文字入口继续工作，真实飞书卡片回调的验收状态独立保留。

## 切换自主处理模式

打开“工作概览”的自主处理卡片，或“连接与设置”／“持续委托”页的自主处理区域，选择模式并点击“切换为…”保存：

- 自动执行：对进入授权范围的新消息进行模型判断；符合已启用规则、目标与资料范围明确时创建真实任务和 Worker，无需 @。明确请求仍可正常执行。
- 仅观察：保留候选需求与判断，不按基础规则自动创建任务；符合条件的受控纯文本草稿仍按原配置工作。
- 关闭基础规则发现：停止基础规则的主动评估；明确 @／私聊请求和独立启用的持续委托仍按各自授权处理。这不是全局停止按钮。

完整区域可逐条启停“工作总结与纪要”“数据汇总”“资料查阅”等已有规则；不允许从此接口创建规则、修改说明或改变持续委托。模式用 eval revision、规则开关用 policy revision 防止旧页面覆盖新配置，冲突时重新选择并保存。模式只更改 eval.mode，保留模型、超时、并发、来源及邮箱配置；基础规则开关只更改 enabled。

切换影响之后的新接单，不回放过去已观察的消息，不自动重建已有任务。已开始的任务请在任务页单独暂停或接管；持续委托的模式保持独立。2026-11-04 按用户要求已将现有三条办公基础规则切为自动执行，仍只允许本人在既有授权范围内触发，不增加飞书平台权限或自动邮件权限。实际当前值以页面服务端读回状态为准。

## 查看执行进展与接管

点击任务打开详情，执行进展每 3 秒读取原生 Harness 记录，显示当前步骤、最近动作、模型与工具累计耗时、步骤数、失败记录及暂停／恢复节点；可展开模型步骤的耗时。只展示动作标签、任务目录内的安全文件名和明确上报的阶段摘要，不展示内部推理、原始命令、工具原文或凭据。数据缺失时如实提示，不编造进度百分比。模型累计包含会话收尾，可能与任务墙钟时间不同；工具调用耗时不等于后台作业的全部运行时间。

这个查询不调用模型、不激活 Worker、不启动任务。仅检查本任务会话，排除继承的父会话历史；查询前后都复核当前任务及来源权限。内部缓存最多 32 个会话、2 秒，页面隐藏时停止轮询。来源撤销时已有浏览器内容仍无法远程收回，但后续查询会被拒绝。原生事件读取失败不影响暂停、接管及报告查看。

“接管”只影响当前任务：立即阻止新的受管工具和排队交付，取消当前生成并停止受管后台作业／子任务，状态先变为“正在移交”。只有后台停止已确认且在途操作归零后才显示“你已接管”；结果不明的操作保留为待核查，不将客户端取消当作外部动作已撤销。控制状态持久保存，新消息或服务重启不会解除接管。

接管完成后，可以在交付物中修改已保存的报告并保留版本。尚未生成报告时，这不等于已经有可编辑正文；直接编辑任务目录文件仍需在本机完成，当前没有网页远程桌面或任意文件编辑器。点击“交还助手”才恢复，助手需读取当前文件、人工版本和要求继续。任务仍使用同一 ID；未完成工作可以建立新执行轮次，今后正确记为 controlReturned，不再误写成 hostRestarted。已经完成的任务交还不会自行重跑。

总结效率约束已加入办公 Skill：独立资料读取合并、每份文件只提取一次，先汇总所需主要指标，逐行全面复核或额外配对分析需任务要求或实际矛盾依据；保留必要统计校验，避免反复装饰性改写，并在收齐资料及交付前内部上报阶段。这是执行指导，真实延迟改善仍需后续任务测量，不是时间 SLA 或硬预算。

## 使用持续委托

打开左侧“持续委托”→“新增委托”，选择“飞书群消息”类型，填写名称及可选目标、选择关注群、可选关键词和处理方式，再保存。例如：名称“整理我的工作记录”；目标“本人发出工作记录后，仅根据本话题事实按已完成、阻碍、下一步整理，保留记录编号；不联系他人”。关键词可填“工作记录、日报”，也可留空交给模型按目标判断。

只可选择当前已授权接收全部消息的 1～3 个群；只针对配置中唯一所有者的原生飞书身份。关键词仅作进入该委托评估的线索，不能绕过模型对目标、来源、确定方向和可交付范围的判断。“自动执行”允许本条规则在基础 observe 模式下创建真实 Ticket 与 Worker，“仅观察”只记录候选判断。普通飞书明确请求仍走原来的任务路径。

保存／编辑／启用后只匹配之后的新消息，不回溯历史消息，不重复接单。事件收件箱记录配置生效回执；回执不是飞书 Trigger，也不会单凭保存目标启动 Worker。多条委托可同时存在，各任务仍有独立会话；同一事件匹配多条委托时，原生评估可在一个有明确范围的任务中记录多个规则依据，不复制该事件开多份重复任务。

暂停阻止新接单，并通过现有任务控制系统暂停尚未结束的自动委托任务。在途操作未确认结束时仍显示正在暂停；不声称撤销已经发生的外部操作。群监听、所有者或委托授权撤销时同样检查这些任务；权限失效时“继续／交还”会被拒绝。重新启用不自动解除已保存的任务暂停，须明确继续。历史任务与交付物保留，内容查看仍按当前来源权限过滤。

配置与回执一并写入现有 SQLite；创建请求幂等，编辑使用 policy revision 防止覆盖，冲突时保留表单输入。Agent 的设置工具不能创建、修改或启停这类委托，只有本机管理入口可操作。委托不自动增加工具、资料范围或邮件发送权限；发信依本人保存的产物交付授权或单次预览确认。当前支持飞书群事件和下述 Codex 日报专用的每日定时／手动触发；文档评论、CI、通用时钟事件及逐委托执行预算留待后续实现，仍受现有全局暂停和 Worker 并发上限控制。

### Codex 会话日报委托

在同一个“新增委托”表单选择“Codex 会话日报”，自行填写名称和汇总目标，再点击“读取今天的本机会话列表”。此操作只获取元数据，不授权读取正文。选择精确项目路径（最多 10 个，涵盖该路径之后的新会话，不递归子目录）或固定会话（最多 20 个），设置北京时间每日运行时刻，并勾选持续读取用于日报的授权。该授权与“Codex 历史”的单日查看授权独立；断开单日查看不会暂停日报，停止日报应暂停对应委托。

选择“自动执行”后，到点由本机 Runtime 建立普通 Harness Ticket 和 Worker，显示在原任务、进展、控制和交付物中。可从卡片“立即运行”汇总今天截至运行时的记录；手动与定时共用所有者／委托／自然日幂等键，每天最多创建一项任务。保存不立即读取正文；保存时已过当日时刻则明天开始，也可立即运行。设备及服务需运行；恢复后只补当天已过且在授权生效后的时刻，不为更早日期新建补跑请求；已经记录的请求仍按原日期恢复并复核授权。重新启用不会自动恢复旧任务。仅观察只保留运行回执，不读取正文或启动 Worker。

日报读取仅走现有 Codex App Server 只读接口，逐 RPC 及提交前复核当前所有者、委托版本和范围。仅取运行日上海时间内的用户／助手文字，最多 20 个匹配会话、30 页、60000 文字字符和 90 秒；无时间、长消息、附件及预算截断均保留限制提示。源快照固定保存在本任务 Trigger，含原生会话／消息 ID、时间及引用编号，报告版本另有 SHA256；不加入草稿箱或独立全文索引。事件列表只展示摘要，不回传完整对话快照。原生工具输出、内部推理、附件正文继续过滤。

Codex 日报 Worker 仅允许 orchestrator_read（本任务来源／任务说明）、orchestrator_artifact 和 orchestrator_report，提交完整 Markdown 正文，由服务登记为固定报告附件。禁用命令、文件修改、检索、通信及子 Agent 工具，也不运行全局 executor.prepare；这是受管工具限制，不等于完整 OS 沙箱。对话中的命令和授权声明按外部资料处理。报告指导区分已完成、讨论／计划、阻碍和下一步，注明“会话中报告完成”与独立验证的区别，引用 S1-M1 等来源并报告覆盖限制；真实模型质量需用户自行创建后联调。

默认仅保存在 Loom；可在委托中选择机器人私聊或沿用已有产物交付设置（可含已经授权的本人邮箱）。没有群聊目的地；邮箱仍独立复核绑定及授权。暂停／修改委托或撤销所有者会在后续读取、任务控制、报告和外部投递前复核；已派发的外部请求不宣称撤销。暂停保留历史，改变项目／会话范围后旧范围的派生产物读取也失效。读取失败不自动循环重试，用户可立即运行重试，读入阶段每天最多 3 次；空记录或观察回执可显式重试，已建任务则沿用任务页控制，不再新建。

实现：src/app/codex-daily.ts、src/codex-delegation.ts、CodexHistory.daily、DelegationBoard 和 CodexDelegationFields；自动化验收见 tests/codex-daily.spec.ts、tests/codex-history.spec.ts。原生接口和页面验证、真实模型日报质量分别记录，不以模拟模型／飞书接口冒充真实日报或收件证据。开发部署不替用户创建委托。

## 权限与边界

入口仅在绑定 `127.0.0.1` 的现有管理服务提供；API 校验 Host、Origin 和专用请求头，不启用跨域访问。它代表已获本机管理权限的个人操作者，要求飞书唯一所有者名单、ownerOnly 及仅飞书部署，不能通过请求参数选择另一个用户。

读取、版本、编辑、导出、草稿控制和邮件操作均复核当前来源权限与任务归属；停止监听相关来源后，后续 API 不再提供相应内容。此前已经发送到浏览器的内容无法远程收回。版本号、控制 revision 和邮件令牌由后端记录校验，不依靠界面按钮是否隐藏。

此入口不是可直接公开部署的多用户服务；跨设备访问、独立网页登录与云端部署仍需另行实现身份网关及对应隔离。完整设备沙箱、任意工作区文件检索、按内容筛选的邮件规则和多人实时合并仍待实现。

2026-11-04 按用户明确要求提供一次 ngrok 临时访问，随后根据“取消账号密码、给领导看效果”的要求改为免登录只读展示。独立 `loom-ngrok` tmux 会话运行 `loom-view` 隧道，云端 Traffic Policy 仅允许 Loom 页面／静态资源、快照、任务进展和交付物等既有读取；拒绝所有 POST／PUT／PATCH／DELETE 等非 GET／HEAD 方法、原始 Codex 历史及项目／会话选项接口。原生 Harness 和其他管理 API 不转发。移除 Origin 前校验它与隧道 HTTPS 域名一致，随后只将 Host 改为既有本机地址；不修改本机服务的同源检查，不开放跨域。此公开链接会展示当前工作空间可读的真实任务、事件及报告，任何持有链接者都能查看；本机原入口保留完整操作。请求检查器关闭，当前策略为权限 0600 的 `.artifacts/ngrok-loom/traffic-policy-view.yml`，不写入版本库。用 `tmux kill-session -t loom-ngrok` 停止并撤销当前入口；本机服务及其他会话继续运行。实际免凭据读取及拒绝写操作的证据见联调记录，正式网页登录、设备身份及多人共享仍待实现。

## 产物交付方式

“交付物”和“连接与设置”页提供“产物交付”，可持久保存三个选项：

- **发回飞书机器人（默认）**：完成后自动发送该版报告文件，群任务回原线程，私聊任务回私聊；若报告来源跨会话或含私聊补充，则转到所有者的机器人私聊。完成摘要仍由原有消息链路发送，文件投递单独记录状态。
- **仅在 Loom 保留**：不自动附加文件；飞书完成摘要保留，可在 Loom 查看正文、导出或改稿。
- **发送到绑定邮箱**：先点击核对绑定邮箱，看到当前本人地址，再点击“授权并保存邮箱交付”。该保存即后续定稿的自动投递授权，无需逐次确认；不向飞书附加文件。163 发送正文及同一版本的文本附件，企业邮箱仍受实际发送权限限制。邮箱换绑后旧授权失效，须重新核对保存。

任务和交付物详情可选择跟随默认，或对这个任务单独覆盖。使用 revision 防止并发覆盖；查看设置不触发模型。切换设置不批量补发历史结果；历史定稿可显式点击“立即投递 vN”。同一版本、目的地只记录一次实际投递；结果不明不自动重发。静默草稿不参与自动交付。

Worker 完成时用 `orchestrator_report.artifact_file` 明确登记任务目录中的 `.md` 或 `.txt` 报告。后端只读取这一个有界 UTF-8 常规文件（最多 40000 字符），拒绝绝对路径、越界、符号／硬链接和二进制，正文及文件名写入不可变版本。发送使用该快照，不再读取可能变化的工作目录。未登记文件时，报告 summary 是交付正文；旧任务可在详情“补充任务目录里的完整报告”登记已有文件为新版本，保留旧摘要，不重跑或自动发送。任意原始数据、XLSX、DOCX、PDF 和完整文件索引仍未接入。

`ResultDelivery` 的持久回执与任务完成状态分离：排队、发送中、飞书已发、SMTP 已接收、仅本地、已取消、受阻、结果待核查。后台总暂停时不派发；任务暂停／接管、版本／要求变化、来源撤权或交付授权撤销使旧排队投递失效，交还后不自行重放。已开始的外部请求可能已提交，实际结果保留，不声称撤回。邮件每个异步发送边界再次核验本人、邮箱账号版本、报告及设置授权。跨会话保护依据已登记的源消息链，尚不等同于完整正文级隐私网关。

实现：`src/app/result-delivery.ts`、`src/app/artifacts.ts`、`src/app/feishu-mail.ts`、`loom/src/client/live/Delivery.tsx`。`tests/result-delivery.spec.ts`、`tests/smtp-mail.spec.ts` 验证真实任务链路和异常控制，外部发送使用替身；真实部署和收件验收另记联调记录。

## 本机 Codex 对话历史

左侧“Codex 历史”连接当前 OS 用户本机保存的 Codex 会话。选择日期后点击“授权读取这一天”，授权独立绑定 Loom 唯一所有者、一个 Asia/Shanghai 自然日及 revision；确认新日期才改变范围。可随时“断开历史读取”。普通概览轮询不读取 Codex，页面不提供发送提示、恢复会话或执行命令的入口。

后端使用已安装的 Codex CLI 的 App Server stdio 协议：initialize 后只允许 thread/list、thread/read（includeTurns=false）、thread/items/list。thread/list 使用 useStateDbOnly=true，包含未归档与归档的本地交互来源；列表先按更新时间筛选可能含当日对话的会话，因此可包含更早创建的会话，且元数据活动不等于必然有当天正文。姓名／标题使用原生会话名称，未命名时显示 ID，不用首条历史问题充当当日摘要。该入口依赖本机已有历史，不读取其他设备或未落地的云端任务。

正文用原生 item 的 startedAtMs（缺失时 completedAtMs）逐条按所选日 00:00 含、次日 00:00 不含过滤；没有原生时间的正文跳过并计数。仅展示 userMessage 的 text 输入，以及 agentMessage 的过程说明／最终回复；工具命令、结果、内部推理、系统／开发者项、自动环境上下文、图片／文件正文不返回。本历史查看入口没有联网模型调用、Codex turn、resume 或会话订阅，也不把查看内容放入 Superagent Trigger、Ticket、Artifact、草稿或飞书／邮箱交付；主动创建的 Codex 日报委托使用上述独立授权。展示经 React 文本／受限 Markdown 渲染，不执行原始 HTML 或远程图片。

每次显式读取启动一个短暂 App Server 进程，完成即关闭；不依赖或重启桌面 App 当前服务，不使用 codex exec/resume 读取历史。最多两次并发读取；每个 RPC 15 秒、整个连接 60 秒，限制输出／页数并显示分页或完整性提示。RPC 错误及 stderr 不原样回传，主动拒绝服务端的工具／审批请求。CLI 版本或存储不支持分页时明确报错，不自动解析私有数据库或日志来补造记录。首次验证环境为 codex-cli 0.157.0，协议按该安装版本生成的 schema 核对。

授权在每个异步 RPC 前后、返回页面前复核；断开或所有者变更后后续查询被拒绝，既有浏览器内容无法远程收回。历史查看入口只保存日期授权，不保存对话正文、索引或 API 凭据；日报委托会按其独立授权保存任务来源快照及报告。接口仍属于本机同源管理范围，不是可公开部署的多用户身份网关，也不是 OS 级隔离。会话原文是外部数据，不能自动成为 Superagent 指令。

实现：src/app/codex-rpc.ts、src/app/codex-history.ts、loom/src/client/live/Codex.tsx。测试：tests/codex-rpc.spec.ts、tests/codex-history.spec.ts。官方协议参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。本轮仅验证只读对话，双向交互、执行委派和 A2A 协作另行设计。
