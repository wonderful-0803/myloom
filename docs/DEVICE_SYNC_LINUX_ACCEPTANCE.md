# 两台 Linux 的自建同步验收（待验证）

本清单仅适用于“跨设备 → 高级设置 → 自建同步（待验证）”。默认方案已改为飞书同步，当前待接入，见 [方案与状态](DEVICE_SYNC.md)。本清单面向同一所有者的两台 Linux。A、B 各运行自己的 Loom 和 Codex，只同步明确选择的项目文字。先用虚构讨论验收，再单独选择真实项目。

## 准备本机同步服务

两台电脑均需已有可进入的 Loom 个人工作空间，以及可用的 Codex CLI。同步服务需要在一台可信、保持在线的 Linux 上运行。仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm sync:local
```

引导固定监听 `127.0.0.1:7421`，首次创建 `~/.local/share/loom-sync/bootstrap.key` 和 `data/hub.sqlite`，再次启动复用凭据和历史。目录权限为0700，凭据及数据库为0600。终端显示文件位置，不打印凭据。`Ctrl+C` 停止服务。

使用独立验收目录时：

```bash
LOOM_SYNC_LOCAL_DIR="$HOME/.local/share/loom-sync-acceptance" LOOM_SYNC_PORT=7421 pnpm sync:local
```

在自己的本机文件查看器中打开 `bootstrap.key`，将内容粘贴到 Loom 的初始化凭据输入框。不要提交凭据文件、发送到聊天或添加到 URL。创建空间后的恢复凭据另行保存；它与服务初始化凭据、一次性邀请分别使用。

服务与桌面窗口独立。需要保持运行时，可在自己的 tmux 会话中执行上述命令，停止该会话里的服务进程即可停服。

## 没有 HTTPS 服务时，用 SSH 联调

同步服务运行在 A 时，A 的 Loom 使用 `http://127.0.0.1:7421`。B 在终端运行下列命令，将 `YOUR_USER@HOST_A` 替换为能通过 SSH 登录 A 的地址：

```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 127.0.0.1:17421:127.0.0.1:7421 YOUR_USER@HOST_A
```

B 的 Loom 使用 `http://127.0.0.1:17421`。核对 SSH 主机身份并保持该终端在线。远程传输由 SSH 加密，服务与转发入口均只监听回环地址。端口17421被占用时可替换。正式服务可按 [部署说明](DEVICE_SYNC.md) 使用可信 HTTPS 地址。

**源电脑与同步服务要分别验收离线行为。** 服务运行在 A 时，首轮停止 A 的 Loom／Codex，保持 A 的同步服务及 SSH 在线。若要让 A 整机关机后 B 仍可读取，须将同步服务放在第三台持续在线的机器。服务断线时本版无法读取历史，没有本机离线缓存。

## 创建测试讨论

A 新建 Codex 项目，例如 `~/loom-sync-demo-home`，开始普通交互会话，讨论以下虚构内容：

> 跨设备验收方案A：对成功的重复退款回调去重。退款金额不能超过实付金额。失败请求的处理暂未确定。

用实际绝对路径授权；B 可使用不同路径，例如 `~/loom-sync-demo-office`。不要填写父目录、整个主目录或其他业务项目。临时执行、子 Agent 和附件正文不属于此轮同步对象。

## 顺序与通过条件

每项记录实际操作时间、设备、项目／会话标识及结果，证据中不保存凭据。“已配对”“已上传”“AI 已读到”分别核对。

| 步骤 | 操作 | 通过条件 |
| --- | --- | --- |
| A 创建空间 | 在跨设备页展开高级设置中的自建同步，创建私人空间，输入服务地址、设备名称和初始化凭据 | 保存恢复凭据；自动同步暂停，尚无采集授权 |
| A 上传项目 | 创建测试项目，填写精确项目路径，勾选读取／上传许可并保存；开启自动同步、立即同步 | 服务端确认时间存在；本轮会话数大于0；原文可见方案A及来源 |
| 空结果提示 | 会话数为0时核对 Codex 实际 cwd、交互来源及覆盖限制 | 明确提示本轮没有上传；不生成虚假的成功回执 |
| 邀请 B | A 为此项目签发邀请；B 使用自己的服务入口和设备名称加入 | 只见获邀项目；不自动采集本机历史；邀请重复使用被拒绝 |
| B 核对上下文 | B 单独允许本机 AI 读取，查看上下文及原会话 | 方案A、约束及来源可核对；AI 授权不自动开启上传 |
| 来源离线 | 停止 A 的 Loom／Codex，保持同步服务在线；B 再读取 | 可读已上传文字；不声称能取回未上传内容 |
| B 形成方案 | 在 B 测试项目讨论“方案B：成功幂等，失败允许重试”，授权并同步。保存方案B，继承方案A，理由填“失败请求仍需恢复”，保留实付约束 | 原文与本人方案分别可查；B 保留独立的原生会话身份 |
| 回到 A | 恢复 A 的 Loom，单独授权 AI 并查看上下文 | 方案A／B、前序关系、理由、原始来源均保留 |
| 断线重试 | 同一内容重复同步；停服后恢复并重试 | 无重复文字；失败轮次不生成新成功时间，恢复后可继续 |
| 暂停 | 暂停自动同步或停止项目采集，再增加文字 | 新轮次不读取／上传；重新启用后才继续；历史保留 |
| AI 撤权 | B 撤销 AI 读取，再通过 MCP 请求 | AI 请求被拒绝；与采集授权分开显示 |
| 设备撤销 | A 撤销 B，B 再读取或同步 | 请求被拒绝后，B 关闭自动同步与 AI 读取并显示撤销状态 |
| 清理 | A 显式删除测试项目服务器记录；停止服务／SSH，按需断开设备 | 该项目不再可读；其他项目及原生会话不变 |

## 实际 AI 接续

在 B 的跨设备页显示 MCP 配置，将这段合并到 B 的 Codex 配置，保留原配置并重新连接 MCP。不要把 A 的程序路径直接复制到 B；此入口依赖 B 本机 Loom 运行。

可让 B 的 Codex 执行只读查询：

> 请从 Loom 读取“跨设备验收”项目，列出当前方案、由A到B的修改理由、继续沿用的约束和未决问题，并注明来源。只查询资料。

核对调用 `loom_list_projects`、`loom_get_context`，需要时使用 `loom_read_session` 或 `loom_read_note`。该项目须已独立授权 AI 读取。原生新聊天自动注入背景、远程 Agent 执行不属于本轮完成条件。

## 自动化复核与剩余验收

```bash
pnpm typecheck
pnpm exec vitest run tests/device-sync.spec.ts tests/device-sync-api.spec.ts tests/codex-rpc.spec.ts tests/docs.spec.ts
pnpm check:loom
pnpm build
pnpm sync:smoke
pnpm sync:smoke:local
pnpm sync:smoke:codex
```

`sync:smoke:local` 实际启动 Linux 引导和服务，检查私有文件、重启后数据／凭据保留及符号链接拒绝。`sync:smoke` 使用真实 HTTP、SQLite、MCP 子进程与两份连接器，Codex 讨论为合成数据。`sync:smoke:codex` 使用已安装 CLI 和空的隔离 `CODEX_HOME` 检查只读连接。自动检查不替代两台真实电脑、实际项目及网络的操作记录。
