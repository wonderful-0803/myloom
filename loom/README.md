# Loom · 织机

## 本仓库中的真实接入（2026-11-04）

新增真实工作空间：http://127.0.0.1:3082/orchestrator/loom/ 。界面复用现有 Superagent 的飞书任务、草稿箱、正文版本、暂停／接管与邮件服务；不用重新配置飞书密钥，不启动第二个机器人或状态库。安装 `pnpm install --ignore-scripts` 后构建 `pnpm build`，由主仓库服务提供页面。完整步骤与权限边界见 [接入说明](../docs/LOOM_SETUP.md)。

以下独立 Express 服务、SQLite、模拟事件及示例补丁说明保留自提供的源包，属于隔离的演示模式，不是上述真实入口的执行后端。

一个用来实践事件驱动 Agent 工作流的本地工作台。React 前端通过 HTTP 和 WebSocket 连接 Node.js 服务，工作规则、任务和交付物存入 SQLite。

当前版本是可运行的流程原型：评估使用关键词与启发式规则；缺陷处理通过确定性补丁修改示例项目，简报使用模板生成。配置模型 API Key 尚不会切换为通用模型执行器。

## 本地运行

需要 Node.js 20、22 或 24，以及 pnpm。首次使用：

~~~powershell
cd D:\Project\luxi\loom\loom
pnpm install
$env:LOOM_PORT = '4579'
pnpm dev
~~~

打开 http://localhost:4579 。不设置 LOOM_PORT 时，默认端口为 4567。

正式构建：

~~~powershell
pnpm build
pnpm start
~~~

正式启动直接提供 dist/client 中的界面；开发模式使用 Vite，热更新与应用 WebSocket 共用服务端口。项目仅允许 better-sqlite3 和 esbuild 执行所需的安装脚本。

## 工作台

- **工作概览**：真实任务计数、需要处理的事项、最近任务、交付物和事件。
- **任务**：按状态筛选，打开详情并查看对应交付物。
- **事件收件箱**：按来源筛选输入，查看处理决定与回执，发送模拟事件。
- **交付物**：阅读补丁说明、简报与报告，下载 Markdown。
- **工作规则**：添加持续规则，选择处理范围，启用或暂停规则。
- **演示实验室**：运行两个成功场景、检查阻塞分支、导出记录或重置演示。
- **连接与设置**：保存飞书应用凭证，并记录接入检查步骤。配置成功和实际收到事件分别显示。

界面采用浅色工作区、固定侧栏和统一的图标、表单、文档阅读样式。支持窄屏导航、键盘焦点、Escape 关闭弹窗、搜索和减少动态效果的系统偏好。刷新页面不会自动弹出交付物。

## 验证一个完整流程

1. 点击“运行演示”，默认运行场景 A。
2. 模拟群消息创建缺陷任务，执行器复现错误、修改文件并运行真实测试。
3. 点击进度条的“交付结果”，查看补丁前后的验证、修改内容和来源任务。
4. 在演示实验室切换到场景 B，或运行阻塞路径。
5. 按需下载交付物，或导出本轮 Markdown / JSON 记录。

场景 A 处理 divide 的除零保护，场景 B 处理 formatPercent 的空值保护。模拟的文档、日历和审批事件也会生成对应模板交付物。

重新运行演示会清理本轮任务、事件、交付物和运行记录，并还原示例文件；工作规则与连接配置保留。

## 目录与数据

~~~text
loom/
  src/client/        React 工作台、组件与样式
  src/server/        API、数据库、Router、规则 Worker、监测逻辑
  src/shared/        前后端共享类型
  loom.db            本机运行数据（不放入源码包）
  dist/              构建结果
loom-sandbox/        演示使用的真实示例文件和测试
~~~

示例目录默认解析为应用旁边的 loom-sandbox，可通过 LOOM_SANDBOX_ROOT 指定。源码运行和构建后运行使用相同的目录解析方式，支持 Windows 路径。

LOOM_PORT 可指定服务端口。连接凭证保存在服务端数据库中；源码包不包含本机数据库、依赖目录或运行配置。

## 检查命令

~~~powershell
pnpm exec tsc --noEmit
pnpm test
pnpm build
~~~

原有四个自动化测试覆盖飞书载荷归一化、加解密和出站失败回退。它们不代表整个 Agent 架构已得到验证。演示会运行示例目录中的真实 Node.js 测试。

## 与 DeepSeek Super-agent 的实现差距

Loom 已演示事件分组、规则匹配、任务分派、订阅消息和结果留存，但以下部分仍需要后续工程工作：

- 实际模型评估与通用工具执行；当前模型可用标志不会改变启发式评估。
- 独立、不可扩张的工单授权与发送者权限边界；当前持续规则不等同于原型中的不可变 Mandate。
- 可持久重放的执行队列、外部副作用幂等与进程重启恢复。
- 独立于主进程的进展监测和恢复；当前 Watchdog 主要记录超时，并将派工标记为失败。
- 完整校验真实回调的签名字段；当前强制校验分支仍存在缺失签名被放行的问题。

真实飞书接入还需要可访问的事件地址、开放平台配置与机器人权限。本地模拟结果不能证明真实工作群已经接通。
